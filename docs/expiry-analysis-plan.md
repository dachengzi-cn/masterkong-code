# 临期分析模块开发计划

## 1. 项目背景与目标

临期分析模块是费用资料分析子系统的重要组成部分，旨在从费用资料中识别临期费用、生成风险预警并提供处理建议，帮助业务人员及时掌控临期费用分布、趋势与风险点。

**本轮目标**：
- 正确识别临期费用记录；
- 生成多维度临期预警；
- 提供可执行的处理建议；
- 与现有费用资料上传、查询功能无缝集成；
- 完成单元测试、集成测试与用户验收测试。

## 2. 数据来源与结构

**主数据源**：`expense_profile` 表（内存/数据库双存储，服务端自动降级）。

费用模板中包含以下临期相关 sheet：
- `临期所别`：按营业所汇总的临期处理费
- `临期形态`：按客户形态汇总的临期处理费
- `临期规格`：按临期产品规格汇总的临期处理费
- `临期门店`：按门店汇总的临期处理费

**关键字段**：
| 字段 | 含义 | 用途 |
|------|------|------|
| `日历年/月` | 费用所属月份 | 时间维度聚合 |
| `组织-营业所` | 营业所 | 区域维度 |
| `客户-客户形态` | 客户形态 | 形态维度 |
| `临期产品` | 临期产品规格 | 规格维度 |
| `客户-通路客户编码` | 门店编码 | 门店维度 |
| `临期处理费金额g` | 临期处理费用 | 金额指标 |

## 3. 核心功能需求

### 3.1 临期识别
- 自动识别 `sheetType` 包含"临期"或 extras 字段包含"临期"的记录；
- 从 extras 中解析月份、维度、金额字段；
- 金额字段模糊匹配：包含"金额"或"金额g"的数值字段；
- 月份字段模糊匹配：包含"年/月"、"月"的字段；
- 对非法/缺失金额做容错处理（视为 0 并记录日志）。

### 3.2 多维度聚合
- 按时间（月度）聚合；
- 按区域（营业所）聚合；
- 按形态（客户形态）聚合；
- 按规格（临期产品）聚合；
- 按门店（通路客户编码）聚合。

### 3.3 临期预警规则
| 预警类型 | 触发条件 | 风险等级 |
|----------|----------|----------|
| 总额预警 | 临期费用总额 ≥ 5 万元 | 高 |
| 环比预警 | 月度环比增幅 ≥ 20% | 高/中/低（按增幅分档） |
| 区域集中 | 单个区域金额占比 ≥ 40% | 中 |
| 形态集中 | 单个形态金额占比 ≥ 40% | 中 |
| 规格集中 | 单个规格金额占比 ≥ 30% | 中 |
| 门店异常 | 单个门店金额 ≥ 1 万元 | 中 |

### 3.4 处理建议引擎
根据预警类型自动生成建议：
- 总额高 → 建议加大促销清库力度，优先消化临期库存；
- 环比上升 → 建议召开临期专项清理会议，追溯上升原因；
- 区域集中 → 建议下沉至重点门店/区域追踪；
- 规格集中 → 建议调整该规格订货量或生产计划；
- 门店异常 → 建议重点拜访并制定门店级促销方案。

### 3.5 数据展示
- **KPI 卡片区**：临期费用总额、环比变化、临期项目数、高风险预警数、涉及门店数；
- **趋势图**：月度临期费用趋势；
- **多维排行榜**：区域/形态/规格/门店 TOP N；
- **预警列表**：按风险等级排序，展示规则命中结果与建议；
- **筛选器**：月份区间、区域、形态、规格、门店。

### 3.6 交互逻辑
- 页面加载时自动读取最新费用资料并计算分析结果；
- 筛选器变更后实时刷新（后端计算，前端展示）；
- 支持导出 Excel 分析报告；
- 空数据时引导用户上传费用资料。

## 4. 分析算法

```text
1. 读取 expense_profile 全部记录；
2. 过滤出临期相关记录（sheetType / extras 含"临期"）；
3. 对每条记录：
   a. 解析月份 → YYYY-MM；
   b. 解析区域、形态、规格、门店（允许缺失）；
   c. 解析金额 → number（容错）；
4. 按维度聚合金额与记录数；
5. 计算环比、占比等衍生指标；
6. 遍历规则引擎生成预警与建议；
7. 返回结构化的 ExpiryAnalysisResult。
```

## 5. 技术方案

### 5.1 后端
- 新增 `ExpiryAnalysisService`，放在 `server/modules/expense-profile/` 或独立 `server/modules/expiry-analysis/`；
- 复用 `expenseProfileService` 读取数据，避免重复实现存储层；
- 在 `expense-profile.controller.ts` 增加 `GET /api/expenses/expiry-analysis` 接口；
- 新增 `ExpiryAnalysisResult` 等类型到 `shared/api.interface.ts`。

### 5.2 前端
- 重构 `ExpiryExpensePage` 为分析看板布局；
- 新增/替换组件：
  - `ExpiryKpiCards`
  - `ExpiryTrendChart`
  - `ExpiryRankingTable`
  - `ExpiryWarningPanel`
  - `ExpiryFilterBar`
- 新增 `expenseApi.getExpiryAnalysis` 调用；
- 移除旧的空框架代码与占位 API。

### 5.3 测试
- **单元测试**：`test/unit/expiry-analysis.service.spec.ts`，覆盖解析、聚合、预警规则；
- **集成测试**：调用 controller API 验证接口返回结构；
- **用户验收测试**：页面上传模板后，验证 KPI、趋势图、预警列表正常展示。

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 模板字段名称变化 | 字段匹配采用模糊匹配，记录未命中字段日志 |
| 数据量大 | 后端一次性读取内存聚合，当前模板数据量在万级以内可接受 |
| 测试环境无数据 | 单元测试使用 mock 数据，集成测试使用内存存储 |

# 业务综合能力评估模块 —— 数据字典说明文档

> 版本：v1.0 ｜ 模块路径：`/capability`（能力评估） ｜ 适用系统：数据分析系统
> 本文档描述「业务综合能力评估」模块的数据指标体系、采集与计算方法、标准化规则、数据库结构与接口约定。

---

## 1. 模块概述

业务综合能力评估模块以「游戏战力图」雷达图为核心呈现，对**所别（营业所）**或**业代**两个层级的业务能力进行 8 维度综合评分，输出综合战力等级（S/A/B/C）、核心优势与关键短板，并支持环比/同比对比与报告导出。

- 评估对象：所别（region）/ 业代（rep），支持全公司汇总视图
- 评估周期：任意月份区间（按月聚合），支持 12 个月以上历史数据
- 评分范围：各维度 0~100 分；总分 = 加权平均（按维度权重）
- 数据来源：完全自动采集，复用现有「客户资料 / 费用资料 / 成交数据集」三类业务数据

---

## 2. 数据指标体系（8 个核心维度）

维度定义以服务端注册表 `server/modules/capability/capability.registry.ts` 中的 `CAPABILITY_DIMENSIONS` 为**单一事实来源**，后续新增指标只需追加一条定义即可。

| # | key | 维度名称 | 方向 | 默认权重 | 数据来源 | 计算方法 | 单位 |
|---|-----|---------|------|---------|---------|---------|------|
| 1 | `sales_achievement` | 业绩达成 | 正向 ↑ | 18% | 费用资料-客户销额 | 评估区间内对象负责客户销额求和 | 元 |
| 2 | `item_distribution` | 品项铺货率 | 正向 ↑ | 13% | 成交数据集 | 区间内对象成交去重规格数 ÷ 全量去重规格数 | % |
| 3 | `atp_performance` | ATP 投入绩效 | 正向 ↑ | 15% | 客户资料 + 费用资料（客户销额/ATP费用） | 付费点销额占比 × 0.6 + 付费点费比健康占比 × 0.4 | 分 |
| 4 | `expiry_control` | 临期品管控 | 反向 ↓ | 12% | 费用资料-临期记录 + 客户销额 | 区间内临期金额合计 ÷ 销额合计 | % |
| 5 | `service_coverage` | 服务覆盖率 | 正向 ↑ | 13% | 客户资料 | 对象负责客户付费点数 ÷ 总点数 | % |
| 6 | `deal_conversion` | 成交转化率 | 正向 ↑ | 12% | 成交数据集 + 客户资料 | 区间内有成交记录的客户数 ÷ 负责客户总数 | % |
| 7 | `store_productivity` | 单店产出 | 正向 ↑ | 9% | 费用资料-客户销额 + 客户资料 | 销额合计 ÷ 总点数合计 | 元/点 |
| 8 | `customer_structure` | 客户结构健康 | 正向 ↑ | 8% | 客户资料 | 付费客户占比 × 0.5 + 合作状态良好占比 × 0.5 | 分 |

> 权重合计 100%。维度权重、启用状态与优势/短板阈值均可通过「维度设置」弹窗调整，配置持久化到数据库（见 §5）。

### 2.1 各维度明细口径

| 维度 | 数据采集标准 | 详细计算说明 |
|------|------------|------------|
| 业绩达成 | 客户销额记录按月、按客户编码汇总 | 客户编码经归一化（`1201/` 前缀保留、`KH` 前缀保留、纯前导零数字补全为 `1201/{数字}`），月份须落在评估区间内，金额取「回单金额/客户销额/门店销额/销额」任一存在字段 |
| 品项铺货率 | 成交数据集（按月、按客户、按规格） | 分子 = 对象客户成交规格去重数；分母 = 区间内全量成交规格去重数（含未铺货规格形成可比基准） |
| ATP 投入绩效 | 客户资料付费点数 + ATP费用计划付费金额 + 客户销额 | ATP 记录金额 ÷ 3 分摊至执行开始日期起覆盖的 3 个月；费比 = 分摊付费金额 ÷ 销额，≤10% 记为健康 |
| 临期品管控 | 费用资料中 sheetType 含「临期」或字段名含「临期/到期」的记录 | 反向维度：临期金额占比越高得分越低，鼓励临期管控改善 |
| 服务覆盖率 | 客户资料中「总点数」「付费点数」字段 | 付费点数合计 ÷ 总点数合计；无付费点数但有 ATP 付费金额的客户按 1 点计入 |
| 成交转化率 | 成交数据集去重客户数 vs 客户资料客户总数 | 区间内有任一成交记录的客户计为转化 |
| 单店产出 | 客户销额与总点数 | 销额合计 ÷ 总点数合计（元/点），衡量单点产出效率 |
| 客户结构健康 | 客户资料中「付费点数」「合作状态」 | 付费客户占比与「合作状态」非（停/终止/未合作/失效/关闭/淘汰/退出）占比各取 0.5 加权 |

## 3. 数据清洗与标准化

### 3.1 清洗与异常值处理

1. **客户编码归一化**：不同来源（客户资料/费用资料/成交数据）的编码统一为同一口径后关联。
2. **月份解析**：兼容 `2026-08`、`2026年8月`、`8月 2026`、`2026.08.01` 等多格式。
3. **金额/数值解析**：支持千分位、货币符号、百分比字符串，非法值按 0 处理。
4. **Winsorize 截断**：标准化前将比较组内值截断至 5%~95% 分位，抑制极端离群值对评分的影响。
5. **缺失维度**：某维度原始值为空时（如无销额数据），该维度不参与总分加权，总分按实际可用维度权重归一。

### 3.2 标准化算法（横向百分位法）

- 比较组：同层级全部对象（评估某所别时与其他所别比较；全公司视图与全部所别并列比较）。
- 得分计算：`score = 组内小于等于该值的对象占比 × 100`（0~100 分）。
- 反向维度（临期品管控）：`score = 100 - 正向百分位`，值越小得分越高。
- 组内全部相等时取 50 分（中性）。

### 3.3 能力等级判定

| 等级 | 得分区间 | 语义 | 雷达图/标签颜色 |
|------|---------|------|----------------|
| 优势（strength） | ≥ 75 | 组内领先 | 绿 `#2FA36B` |
| 中等（medium） | 60 ~ 74 | 组内中等 | 黄 `#E9A12B` |
| 短板（weak） | < 60 | 组内落后 | 红 `#E14A3B` |

> 优势/短板阈值（默认 75 / 60）可在「维度设置」中按维度调整。

### 3.4 综合战力等级

| 等级 | 总分区间 | 标签 |
|------|---------|------|
| S | ≥ 85 | 卓越 |
| A | 70 ~ 84 | 优秀 |
| B | 55 ~ 69 | 良好 |
| C | < 55 | 待提升 |

## 4. 数据来源字段映射

评估完全复用现有三类业务数据集，无需额外录入：

| 数据来源 | 存储表 | 使用字段 |
|---------|--------|---------|
| 客户资料 | `customer_profile` | `region`（所别）、`customer_code`（客户编码）、`extras`（客户经理/业代、总点数、付费点数、合作状态） |
| 费用资料 | `expense_profile` | `sheet_type`（客户销额 / ATP费用 / 临期）、`customer_code`、`extras`（时间-年/月、回单金额、客户销额、门店销额、销额、执行开始日期、计划付费金额、临期相关字段） |
| 成交数据集 | `data_record` | `content` JSONB（人员-业代、品牌、产品-规格、日期字段、客户编码） |

## 5. 数据库表结构

### 5.1 `capability_dimension_config` —— 维度配置表

保存用户自定义的维度权重/启用状态/阈值。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid PK | 主键 |
| dimension_key | varchar(100) UNIQUE | 维度 key，对应注册表 |
| name | varchar(255) | 维度名称 |
| weight | numeric(5,2) | 权重（0~1），默认 0.125 |
| enabled | boolean | 是否启用 |
| threshold_high | integer | 优势阈值，默认 75 |
| threshold_low | integer | 短板阈值，默认 60 |
| sort_order | integer | 展示排序 |
| _created_at / _updated_at | timestamptz | 创建/更新时间 |
| _created_by / _updated_by | user_profile | 创建/更新人 |

### 5.2 `capability_user_scope` —— 用户数据范围表（RBAC 预留）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid PK | 主键 |
| user_id | varchar(255) | 用户标识 |
| region | varchar(255) | 授权可见所别 |
| _created_at / _created_by | timestamptz / user_profile | 创建信息 |

**权限规则**：表中存在该用户的授权所别记录时，评估仅返回授权所别范围数据；无任何配置（或表不存在）时全量可见。本阶段仅预留，后续接入角色体系。

## 6. 后端接口约定

基础路径：`/api/capability`（所有接口需登录，取 `req.userContext.userId`）

| 方法 | 路径 | 说明 | 关键参数 |
|------|------|------|---------|
| GET | `/api/capability/options` | 下拉选项：所别/业代（随所别联动）/有数据月份 | — |
| GET | `/api/capability/dimensions` | 维度元信息 + 当前权重/阈值/启用状态 | — |
| PUT | `/api/capability/dimensions` | 保存维度配置（upsert） | `{ dimensions: [{ key, weight?, enabled?, thresholdHigh?, thresholdLow? }] }` |
| GET | `/api/capability/score` | 核心评估：维度得分 + 总分/等级 + 对比 | `level, region, salesRep, monthFrom, monthTo, compareType` |
| GET | `/api/capability/insights` | 解读：优势/短板/结论/建议 | 同 score |
| GET | `/api/capability/export` | 导出 xlsx 报告（3 工作表） | 同 score |

### 6.1 参数说明

| 参数 | 取值 | 说明 |
|------|------|------|
| level | `region` / `rep` | 评估层级（所别 / 业代） |
| region | 所别名称 | 缺省 = 全公司汇总；level=rep 时必填 |
| salesRep | 业代完整名称（含编号） | 业代评估时指定，来自 options 下拉 |
| monthFrom / monthTo | `YYYY-MM` | 评估月份区间，缺省取有数据的最新月份 |
| compareType | `none` / `mom` / `yoy` | 无对比 / 环比（上月）/ 同比（去年），对比期无数据时降级为 null |

### 6.2 `score` 响应结构（节选）

```jsonc
{
  "level": "region",
  "region": "嘉定城区所",          // 空字符串 = 全公司
  "monthFrom": "2026-07",
  "monthTo": "2026-08",
  "compareType": "mom",
  "scores": [{
    "key": "sales_achievement",
    "name": "业绩达成",
    "score": 100,                  // 0~100 标准分
    "level": "strength",           // strength | medium | weak
    "rawValue": 6345747.54,        // 原始指标值
    "rawLabel": "¥6,345,748",      // 展示文案
    "weight": 0.18,
    "compare": { "mom": 3.2 }      // 对比期得分差（可空）
  }],
  "totalScore": 75.3,
  "totalLevel": { "code": "A", "label": "优秀", "color": "#1E6FEB", "minScore": 70 },
  "compare": {
    "type": "mom",
    "label": "2026-06 ~ 2026-07",
    "totalScore": 73.7,
    "scores": [{ "key": "...", "score": ..., "rawValue": ... }]
  }
}
```

### 6.3 性能保障

- 服务端 10s TTL 响应缓存（options / dimensions / score 三组），重复查询直接命中。
- 单次评估 = 三次数据拉取（客户资料、费用资料、成交记录）+ 内存聚合，实测接口响应 < 1s。
- 前端图表按需渲染（echarts），页面级懒加载。

## 7. 维度扩展指南

新增一个评估指标只需 3 步（前端零改动）：

1. **注册表**：在 `CAPABILITY_DIMENSIONS` 追加定义（key/name/direction/dataSource/calcMethod/unit/defaultWeight/thresholdHigh/thresholdLow/sortOrder/suggestionText），并扩展 `CapabilityDimensionKey` 联合类型。
2. **分析器**：在 `capability-analyzer.ts` 的 `buildObjectRawMetrics` 中补充该指标的原始值聚合（metrics 中新增 key），并在 `buildObjectMetrics` 中完成计算。
3. **共享类型**：如需要新的原始值语义，可在 `shared/api.interface.ts` 补充注释说明（score 结构本身通用，无需改动）。

前端雷达图、明细表、解读面板与导出均按注册表/接口响应自动渲染新维度。
